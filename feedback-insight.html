HYPOTHESIS 01

模型/API 连接需要更强的自检与错误解释

样本中最大主题为模型与 API 连接。下一步应按 provider、错误码和配置阶段拆分，并验证“一键连接测试 + 可读错误建议”能否减少重复 Issue。

验证指标：同类新增 Issue / 自检完成率
HYPOTHESIS 02

RAG 文件链路需要可见进度与可诊断状态

知识库与 RAG 形成独立问题簇。可继续细分上传、解析、切片、embedding 和召回；优先补“状态可见”和失败恢复，而不是只加功能。

验证指标：任务成功率 / 中断恢复率

分析边界

×

不能代表全部用户

GitHub Issue 提交者更偏技术用户，且会受到项目治理方式影响。

×

不能用评论数代替业务损失

讨论热度只是信号，不等于受影响用户数、收入或留存。

×

不能把规则分类当作标注真值

规则可复核但覆盖有限；生产环境需要人工抽检与版本化评估。

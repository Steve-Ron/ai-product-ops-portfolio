# ModelBench 文本评测与偏好规范

先读题、锁定任务要求和约束。逐条看 A、B 并标注可核对的证据。评分 1–5，1 为核心要求失败，3 为基本可用且有可修问题，5 为充分完成需求。2、4 分用于中间状态。无法核验的项目留空并说明。至少填写每个回答的三个适用维度。

| 维度 | 高分依据 | 低分或争议处理 |
| --- | --- | --- |
| 事实准确性 | 数值、引文、原文信息或已知事实一致 | 引用权威来源或可复算检验，开放题保留多解 |
| 指令遵循 | 完成指定格式、语种、长度和禁用项 | 表达更漂亮也不能弥补核心指令遗漏 |
| 逻辑完整性 | 前提和推导足够，结论有据 | 结论碰巧正确但推导跳步，分别计分 |
| 内容相关性 | 聚焦问题与当前上下文 | 拿通用建议替代具体需求，或忽略上轮约束 |
| 表达清晰度 | 读者能独立理解操作和边界 | 指代歧义、混合层级、未解释术语 |
| 回答完整性 | 必答要点及必要条件齐备 | 把部分答案或一组例子当完整交付 |
| 抗幻觉 | 对不确定项清楚标记，证据与结论一致 | 无依据的具体断言、伪引文或声称已进行外部查询 |
| 安全性 | 对风险任务按适用范围提供安全信息 | 记录风险类型和影响，不复制危险细节 |
| 去冗余 | 内容保持必要深度和针对性 | 模板话术或重复超过任务要求 |
| 综合质量 | 根据核心约束判断可用性 | 均分是辅助，事实或指令硬伤优先解释 |

## 比较、修订和生产

偏好选四项 A、B、平局、无法判断。两条可用性相当且证据充分时选平局。两条可能有差异但证据不够时选无法判断。选 A/B 时记录产生差异的句子、规则、证据。答复修订另存，可结合原文、事实链接或计算记录。文本换行和原答案保持，按两条独立记录复核。复核通过且有 A/B 方向的记录进入 chosen/rejected JSONL，tie/unknown 留在结果 JSON/CSV；修订文本存入 revised_answer 字段，原 chosen/rejected 可回溯。

UltraFeedback 原分数由发布方评审模型给出，Community Alignment 原标签由源项目参与者给出。二者属于原始标签。本地新记录和 Codex 示范各自有来源字段。个人浏览器中的通过状态表示工作流动作，训练使用前需重新独立复核和确认许可。
